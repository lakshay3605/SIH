# Aadivaani — Evolution & Migration Plan

**Document**: `docs/aadivaani_migration_plan.md`  
**Version**: 1.0 (Phase 0 Deliverable)  
**Scope**: Strategy to evolve the existing repository into the complete, production-grade Aadivaani offline translation system.

---

## 1. Migration Philosophy & Rules of Engagement

1. **Preserve Working Assets**: Do not delete existing valid scripts (`script_validator.py`, `dataset_builder.py`, `metrics.py`), reports, or original datasets.
2. **Eliminate Mocks & Simulations**: Replace all simulated training, hardcoded metrics, and placeholder stubs with verifiable, deterministic code and real weights.
3. **Target Device Reality First**: All architectural choices are constrained by:
   - **Android 9+ (API 28+)**
   - **2GB Total RAM budget** (Application resident memory limit < 400 MB)
   - **ARMv8 / ARMv7 CPU** execution (no NPU or CUDA reliance)
   - **100% Offline**: No network calls permitted in production runtime.
4. **Phased Rollout**: Implement Santali end-to-end first to establish the production pipeline, then expand to Ho and Mundari.

## 3. Detailed File Action Plan

### Files to Preserve Intact (Read-only / Kept for reference)
- `src/script_validator.py`: Preserved and extended for Warang Chiti and Mundari.
- `src/metrics.py`: Preserved; contains robust pure-Python BLEU/chrF calculation.
- `data/flores_pairs.json`: Preserved as high-quality standard benchmark.
- `data/master_dataset.csv`: Preserved as initial seed cache.
- `outputs/aakansha_training_report.md` & `outputs/post_training_results.json`: Kept as audit record.
- `SIH/hindi-santali-translator/scripts/train_indictrans2.py`: Preserved; contains clean CPU LoRA code with custom linear layers.

### Files Requiring Complete Modification / Rewrite
- `src/train_lora.py`: Rewrite from scratch into a functional PyTorch + HuggingFace Seq2SeqTrainer script that loads real weights and outputs real `.safetensors`.
- `src/inference.py`: Rewrite to use the real ONNX Runtime engine with fallback to the local phrase cache.
- `src/evaluate.py`: Rewrite to compute actual metrics by running hypotheses generated by the ONNX/PyTorch model against reference sets.
- `scripts/export_onnx.py`: Fix error handling so it fails loudly instead of creating dummy 27-byte files. Export real encoder and decoder with past_key_values.
- `HindiSantaliApp/.../TranslationModelDownloader.kt`: Replace dynamic web downloader with a robust local asset loader or sideload manager for true offline packaging.
- `HindiSantaliApp/.../SantaliTtsEngine.kt`: Replace naive Latin transliteration with authentic phoneme mapping or offline small-footprint acoustic model.

### Files to Create in Phase 1 & 2
- `src/core/warang_chiti_validator.py`: Script validation for Ho Warang Chiti (`U+118A0`–`U+118FF`).
- `src/core/mundari_validator.py`: Script validation for Mundari texts.
- `scripts/export/quantize_int8.py`: Real Dynamic/Static INT8 quantization using `onnxruntime.quantization`.
- `scripts/export/optimize_kv_cache.py`: Merge past-key-values into ONNX decoder for fast autoregressive generation on mobile CPU.
- `tests/test_script_validators.py`: Formal unit tests.
- `tests/test_onnx_inference.py`: Formal verification of exported ONNX latency and correctness.

## 4. Phase-by-Phase Roadmap

### Phase 0: Repository Audit & Planning (CURRENT)
- [x] Full source code inspection and line-by-line verification.
- [x] Environment audit and dependency assessment.
- [x] Execution of existing scripts and identification of simulated code.
- [x] Creation of `docs/repository_audit.md`, `docs/aadivaani_migration_plan.md`, `docs/architecture.md`, `docs/technical_risks.md`.
- [ ] User review and approval.

### Phase 1: Data Infrastructure & Tri-Language Dataset Engineering
- Clean and de-duplicate the 4,046 Santali pairs. Remove ungrammatical synthetic combinations.
- Aggregate authentic parallel datasets:
  - **Santali**: Additional FLORES, Bible corpora, Sangraha verified subsets.
  - **Ho**: Collect Ho-Hindi parallel data (Devanagari and Warang Chiti scripts).
  - **Mundari**: Collect Mundari-Hindi parallel data.
- Build unified bilingual and multilingual data split pipeline with locked test sets.
- Build high-speed phrase cache generator (`trie` / SQLite).

### Phase 2: Teacher Model & IndicTrans2-200M Distilled Fine-Tuning
- Fine-tune `ai4bharat/indictrans2-indic-indic-dist-200M` on the curated multi-language dataset.
- Implement bidirectional adapters (Hindi $\rightarrow$ Tribal and Tribal $\rightarrow$ Hindi).
- Verify real training loss convergence and validation chrF++ on GPU/Cloud.
- Save valid `.safetensors` checkpoints.

### Phase 3: Model Compression & ONNX Mobile Export
- Merge LoRA adapters into base weights.
- Export Seq2Seq encoder and decoder to ONNX with past_key_values enabled.
- Apply INT8 Quantization (dynamic quantization on Linear layers).
- Validate output parity between PyTorch and INT8 ONNX (chrF++ drop < 1.0 point).
- Measure cold-start load time, memory peak, and latency per token on x86 and ARM CPU.

### Phase 4: Android Engine & Offline Packaging
- Integrate exported INT8 ONNX models and SentencePiece models directly into the Android app.
- Update `HindiSantaliTranslator.kt` to use greedy search with proper KV-cache tensor reuse.
- Implement dual-engine inference:
  - **Tier 1**: In-memory phrase cache (response < 5ms).
  - **Tier 2**: INT8 ONNX Model (response < 1.5s).
- Verify memory consumption remains strictly under 400 MB on Android.

### Phase 5: Voice Pipeline (ASR & TTS)
- Integrate offline Hindi ASR (SherpaOnnx INT8 bundle).
- Implement phoneme-based offline tribal speech synthesis.
- Connect end-to-end: Speech $\rightarrow$ Text $\rightarrow$ Translation $\rightarrow$ Speech.
