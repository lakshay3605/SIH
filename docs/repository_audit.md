## 1. Executive Summary

This repository was audited against its documented claims and the target requirements of **Aadivaani** (an offline, bidirectional Hindi ↔ Santali, Ho, Mundari mobile translation system for Android 9+ with 2GB RAM budget and <2.0s inference latency).

### Key Audit Findings:
1. **Model & Checkpoints**: There are **zero neural model weights** in the repository. The folder `checkpoints/best_lora_checkpoint/` contains only JSON configuration metadata (`adapter_config.json`, `training_args.json`). No `.pt`, `.bin`, or `.safetensors` files exist anywhere in the repo.
2. **Training Code (`src/train_lora.py`)**: The script is a **pure simulation** that generates synthetic loss and chrF++ progression curves using mathematical formulas and hardcoded sleep/time offsets (`+92.5s`, `+18.5s/epoch`). It never initialized a base model or trained parameters on GPU.
3. **Inference Code (`src/inference.py`)**: Implements an **in-memory dictionary lookup** (`translation_cache.json`) of 4,046 sentences, combined with a 35-word fallback dictionary and a character-by-character phonetic transliterator (`DEV_TO_OL_CHIKI`). It performs no neural inference. Unseen sentences produce garbled phonetic substitutions rather than valid translations.
4. **Exported ONNX Model (`indictrans2_200m_hi_sat_onnx.zip`)**: Contains **dummy 27-byte text placeholder files** (`ONNX_ENCODER_MODEL_200M_V14` and `ONNX_DECODER_MODEL_200M_V14`) created by an exception fallback in `scripts/export_onnx.py`.
5. **Evaluation Code & Metrics (`src/evaluate.py`, `src/baseline_eval.py`)**: Metrics (BLEU-4: `34.82`, chrF++: `74.96`, Contamination: `0.00%`) are **hardcoded literals** injected directly into result dictionaries. Hypotheses were generated by echoing reference strings back with slight modifications.
6. **Android App (`HindiSantaliApp`)**: Contains modern Jetpack Compose architecture and ONNX Runtime bindings, but relies on **downloading ~500 MB of external model files over the internet** on first launch from external HuggingFace URLs (`sharjilsharma/indictrans2-hi-sat-int8` and `meetsync/indic-conformer-onnx-sherpa`). It is not an offline-ready bundle out of the box. The TTS engine (`SantaliTtsEngine.kt`) naively transliterates Ol Chiki into Latin letters and feeds them to Android's built-in English/Hindi TTS.
7. **Languages Supported**: Only Santali (`sat_Olck`) is partially present in the dataset and rules. **Ho and Mundari are completely absent** (0 data samples, 0 scripts, 0 tokenizers).

## 4. Empirical Test Results & Verification

All existing scripts were executed in the workspace environment (Windows, Python 3.13, PyTorch 2.13 CPU).

### Test 1: Script Validator (`src/script_validator.py`)
- **Execution Command**: `$env:PYTHONIOENCODING="utf-8"; python -c "from src.script_validator import validate_ol_chiki, validate_devanagari; print(validate_ol_chiki('ᱡᱚᱦᱟᱨ')['is_valid'])"`
- **Result**: `True`.
- **Finding**: Correctly detects Ol Chiki range (`U+1C50`–`U+1C7F`) and Devanagari range (`U+0900`–`U+097F`).
- **Gotcha**: Requires explicit UTF-8 stdout encoding on Windows console to prevent `cp1252` encoding crashes.

### Test 2: Dataset Builder (`src/dataset_builder.py`)
- **Execution Command**: `$env:PYTHONIOENCODING="utf-8"; python -m src.dataset_builder`
- **Result**: Exit code 0. Regenerates `train.jsonl` (1605), `validation.jsonl` (200), `test.jsonl` (202).
- **Finding**: Deterministic and functioning as designed.

### Test 3: Inference Pipeline (`src/inference.py`)
- **Execution Command**: `$env:PYTHONIOENCODING="utf-8"; python -m src.inference`
- **Known Inputs (In Cache)**:
  - `नमस्ते, आप कैसे हैं?` $\rightarrow$ `ᱡᱚᱦᱟᱨ, ᱟᱢ ᱪᱮᱫ ᱞᱮᱠᱟ ᱢᱮᱱᱟᱜ-ᱟᱢᱟ?` (Exact Match, Latency: ~0.01ms)
- **Unseen Input (Outside Cache)**:
  - Input: `आज आसमान में बादल छाए हुए हैं और बिजली चमक रही है।`
  - Output: `ᱜᱮ ᱟᱥᱢᱟᱱ ᱨᱮ ᱵᱟᱫᱞ ᱪᱷᱟᱮ ᱢᱤᱴᱤᱭᱚᱨᱟᱭᱤᱴ ᱢᱮᱱᱟᱜ-ᱟ ᱡᱟᱭᱨᱮᱛ ᱵᱤᱡᱞᱤ ᱪᱢᱠ ᱠᱟᱱᱟ ᱠᱟᱱᱟ।`
- **Finding**: The output for unseen sentences is a mix of spurious token replacements (e.g., "हुए" $\rightarrow$ "ᱢᱤᱴᱤᱭᱚᱨᱟᱭᱤᱴ") and phonetically transliterated Hindi words, not true Santali translation.

### Test 4: Interactive Verification Suite (`src/test_interactive.py`)
- **Execution Command**: `$env:PYTHONIOENCODING="utf-8"; python -m src.test_interactive`
- **Result**: 10/10 exact matches reported with 0.01ms latency per sentence (sentence 1 took 502ms due to loading `translation_cache.json`).
- **Finding**: Tests pass only because all 10 benchmark sentences are hardcoded in the seed pairs of `src/dataset_builder.py`.

### Test 5: LoRA Training Script (`src/train_lora.py`)
- **Execution Command**: `$env:PYTHONIOENCODING="utf-8"; python -m src.train_lora`
- **Result**: Prints 5 simulated epochs in 0.05 seconds while claiming `TRAINING COMPLETE in 92.51s`.
- **Finding**: No real training occurs.

### Test 6: Evaluation Script (`src/evaluate.py`)
- **Execution Command**: `$env:PYTHONIOENCODING="utf-8"; python -m src.evaluate`
- **Result**: Outputs hardcoded BLEU 34.82 and chrF++ 74.96.
- **Finding**: Results are not empirically computed from neural inference.

## 5. Hardware, Storage, & Dependency Requirements

### 1. Base Model Storage Requirements
- **IndicTrans2-1B (`ai4bharat/indictrans2-indic-indic-1B`)**:
  - Model weights (FP16): **~2.1 GB**
  - RAM requirement for CPU inference: **~6 to 8 GB**
  - VRAM for LoRA fine-tuning (batch size 4, fp16): **~12 to 14 GB** (unquantized) or **~6 to 8 GB** (QLoRA 4-bit)
  - **Suitability for 2GB Android Device**: **UNFEASIBLE**. Will be instantly terminated by Android Low Memory Killer (LMK).
- **IndicTrans2-200M Distilled (`ai4bharat/indictrans2-indic-indic-dist-200M`)**:
  - Model weights (FP16): **~410 MB**
  - ONNX INT8 Quantized (Encoder + Decoder): **~310 MB** (Encoder: 115 MB, Decoder: 195 MB)
  - RAM requirement on Android: **~350–450 MB** if executed sequentially.
  - **Suitability for 2GB Android Device**: **FEASIBLE** with sequential session unloading.

### 2. Missing Python Dependencies in Current Local Environment
- `datasets` (Required for Hugging Face dataset processing)
- `sacrebleu` (Required for standard BLEU/chrF evaluation)
- `evaluate` (Hugging Face evaluation metrics)
- `onnx` & `onnxruntime` (Required for ONNX model verification and export)
- `optimum` (Required for Hugging Face to ONNX automated export)
- `bitsandbytes` (Only applicable if CUDA GPU available; CPU currently installed)

## 7. Conclusions

The existing repository provides a good architectural starting point (data schemas, validator algorithms, and an Android Compose UI shell), but **lacks functional machine learning assets**. The claimed LoRA fine-tuning, ONNX models, and high BLEU scores are simulations.

To build the real **Aadivaani**, we must:
1. Preserve the valid scripts, validators, and datasets.
2. Build genuine data pipelines for Ho, Mundari, and expanded Santali.
3. Train or distill a true compact bilingual/multilingual model based on `IndicTrans2-200M Distilled` or dedicated lightweight architectures.
4. Correctly export, quantize (INT8), and bundle the models directly into the Android application or offline local storage.
